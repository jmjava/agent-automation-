# H4 best-of-n: tournament with a deterministic scorer and a premium picker

Proves tournaments pay off only when the picker is bound by deterministic hard gates.

## Owns these Agent Queue lines

H4.1 through H4.5.

## Behavior

1. Same task to N seats with different `model`/`params` (default: `composer-2.5`, one thinking model, one fast model), all on the same `startingRef`, `autoCreatePR: false`.
2. Collect each candidate's diff from run git metadata; apply it in a scratch worktree.
3. Scorer: **hard** = suite passes, `Files:` honored; **soft** = mutation probe score, diff size, token cost. A candidate failing any hard gate is out.
4. Premium reviewer sees only surviving candidates and returns `accept <id>` or `rewrite` or `reject`.
5. `decide_apply` (ported from `slm-setup/eval/orchestrate.py`): accept of an unproven candidate → `blocked:accept_unproven`; rewrite is re-scored before apply; reject applies nothing.
6. Receipt lists per-candidate scores, the pick, cost per candidate, and the apply decision.

## Files

`harnesses/h4-best-of-n/run.ts`, `scorer.ts`, `apply-gate.ts`, `cases.json`, `README.md`, `evals/h4.eval.ts`.

## Offline mode

Scripted candidates with known layer outcomes. Tests: the picker never applies a candidate that failed a hard gate; a rewrite that fails re-scoring is blocked; the pick is stable for the fixture.

## Done when

Receipt shows scores, pick, and cost for three live candidates; eval asserts stability on the scripted fixture.
