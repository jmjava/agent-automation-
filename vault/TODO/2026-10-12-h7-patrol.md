# H7 patrol: the pool watchdog

Proves overnight runs need a watcher that is not a worker.

## Owns these Agent Queue lines

H7.1 through H7.5.

## Behavior

1. Runs on a schedule (Cursor Automation, cron, "no repository" mode) or as a BDK schedule.
2. `GET /v1/agents` filtered to `metadata.pool = *`; load each agent's runs.
3. Classify each seat: running within budget · running past budget · finished without PR · `ERROR` · `EXPIRED` · PR with failing checks · PR green but unmerged for more than X hours.
4. Action table (every action idempotent, recorded under `patrol/<agentId>/<action>` so a re-run does not repeat it):

| State | Action |
| --- | --- |
| running within budget | noop |
| running past budget | `cancel`, `block_task` with reason |
| finished without PR | nudge: one follow-up run with a fixed message |
| ERROR / EXPIRED | `block_task`, write pitfall to daily note |
| PR failing checks | nudge once; second time `block_task` |
| PR green, unmerged > X h | daily note reminder only |

5. Exponential backoff when a patrol finds no work; any new seat resets it.
6. Daily-note summary per patrol run.

## Files

`harnesses/h7-patrol/run.ts`, `classify.ts`, `actions.ts`, `fixtures/agents-*.json`, `README.md`, `evals/h7.eval.ts`.

## Offline mode

Fixture agent lists in every state; assert the action table and idempotency on a second pass.

## Done when

The patrol runs on a schedule for a day over H1 seats; its daily-note summary matches the H1 receipts; no action was taken twice.
